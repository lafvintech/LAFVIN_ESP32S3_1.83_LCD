1. Quick Start
==============

This chapter helps you quickly check whether the ESP32-S3 1.83-inch LCD
Development Board is working properly after you receive it.

The board is usually preloaded with factory test firmware before shipping.
After power-on, the LCD shows basic test information, such as SD card capacity,
Flash size, sensor data, Wi-Fi scan results, backlight level, and other status
information. These items help you confirm that the display, storage, sensor,
wireless functions, and backlight control are working.

.. note::
   This chapter is only a quick start for unpacking, functional checking, and
   firmware testing. To learn the full development workflow, continue with the
   :ref:`Arduino Tutorial <arduino_tutorial>`.

Preparation
-----------

* Connect the board with a USB Type-C data cable. A charging-only cable can
  power the board, but it cannot be used for flashing or serial communication.
* If you need to view serial logs, make sure the computer can detect the board's
  serial port.
* If you want to use the online flashing tool, use Chrome, Edge, or another
  browser that supports the Web Serial API.
* If you want to check SD card information, insert the 1 GB TF card included in
  the kit.

Step 1: Connect the Board
-------------------------

1. Connect the board to your computer with a USB Type-C data cable.
2. Wait for the board to power on and boot.
3. Check whether the 1.83-inch LCD turns on.
4. If the board does not start immediately, press the **RST** button once to
   restart it.

Expected Result
~~~~~~~~~~~~~~~

The screen should show the factory test firmware interface. The interface may
vary slightly between firmware batches, but it usually includes one or more of
the following items:

* SD card capacity or SD card detection status
* Flash capacity
* QMI8658A sensor data
* Wi-Fi scan results
* Backlight level or backlight adjustment status

If this information is displayed correctly, the main onboard functions of the
development board are working.

Step 2: Restore the Factory Test Firmware
-----------------------------------------

If the board does not show the factory test interface, or if you have already
flashed another program and want to restore the factory state, use the
:ref:`online_flasher` to reflash the factory test firmware.

Online flashing is suitable for the following situations:

* Restoring the factory test firmware
* Checking whether the board functions work properly
* Quickly trying other official firmware
* Flashing firmware without installing Arduino IDE or ESP-IDF

.. warning::
   Flashing new firmware overwrites the program currently running on the board.
   If you need to keep the current program, make sure you already have the
   corresponding source code or firmware file.

Step 3: Continue with the Tutorials
-----------------------------------

After the quick check is complete, choose the next tutorial according to your
development path:

* If you are a beginner, or if you want to upload example programs quickly,
  read the :ref:`Arduino Tutorial <arduino_tutorial>`.
* If you only want to try different firmware functions, continue using the
  :ref:`online_flasher` to select and flash other firmware.

FAQ
---

**The screen does not show anything**

* **Symptom**: After connecting USB, the LCD does not turn on or does not show
  the factory test interface.
* **Possible causes**: The USB cable cannot provide stable power, the board did
  not boot normally, or the factory firmware has been overwritten.
* **Solution**: Use another USB data cable, press **RST** once, or restore the
  factory test firmware with the :ref:`online_flasher`.

**The computer does not detect a serial port**

* **Symptom**: No available serial port appears in Device Manager or in the
  development tool.
* **Possible causes**: A charging-only USB cable is being used, the USB driver
  is not installed, or the USB connection is unstable.
* **Solution**: Use another USB Type-C data cable, try another USB port, and
  refer to :ref:`preparation` to check the development environment and driver
  installation steps.

**The online flasher cannot connect to the board**

* **Symptom**: The browser cannot select a serial port, or the connection fails
  after you click Connect.
* **Possible causes**: The browser does not support the Web Serial API, the
  serial port is being used by another program, or the board is not in a
  flashable state.
* **Solution**: Use Chrome or Edge, close programs that may be using the serial
  port, such as Serial Monitor. If the problem persists, hold **BOOT**, press
  **RST** once, release **BOOT**, then reconnect and flash again.
